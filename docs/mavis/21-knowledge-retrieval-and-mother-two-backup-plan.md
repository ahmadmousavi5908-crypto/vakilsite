# 21 — برنامه اتصال دانش MAVIS و ارتقای بکاپ مادر دو

**وضعیت:** برش جست‌وجوی داخلی admin-only پیاده‌سازی و تست شده؛ اتصال کامل Lawyer Copilot، manifest مرکزی و تأیید منابع حقوقی همچنان باز است.  
**تاریخ ثبت:** 2026-11-06  
**دامنه:** اسناد، دانش حقوقی، بازیابی MAVIS و حفاظت از وضعیت تأییدشده Vakilsite  
**اصل حاکم:** این سند مجوز تغییر UI، کد اجرایی، دیتابیس، انتشار یا ادغام شاخه‌ها نیست.

## 1. اتصال دانش به MAVIS — وضعیت واقعی و گام بعدی

### هدف
استفاده از دانش حقوقی موجود پروژه بدون ساخت کتابخانه موازی، با حفظ مرز بین جست‌وجوی عمومی آفلاین، پژوهش داخلی و دستیار گفت‌وگومحور آینده.

### آنچه اکنون واقعاً پیاده‌سازی شده است
یک برش **بازیابی قطعی و فقط‌خواندنی برای پژوهش داخلی مدیر/وکیل** وجود دارد:

- `src/lib/mavis/knowledge-registry.js` رکوردهای موجود کتابخانه حقوقی را به رجیستری runtime تبدیل می‌کند؛ منبع داده همان `src/data/legal-library/` و `src/lib/legal-library.js` است، نه یک کپی موازی.
- `src/lib/mavis/knowledge-search.mjs` جست‌وجوی فارسی قطعی و رتبه‌بندی واژگانی را انجام می‌دهد.
- `POST /api/mavis/knowledge-search` یک مسیر داخلی و admin-only است؛ احراز مدیر، کنترل Origin، محدودیت اندازه بدنه، rate limit و پاسخ no-store دارد.
- مسیر API نتیجه بازیابی را با `buildLegalEvidence` و `buildLegalResearchDossier` همراه می‌کند تا وضعیت منبع، ارجاع و خلأهای شواهد قابل مشاهده بماند.
- تست‌های `tests/mavis/knowledge-search.test.mjs` مجموعه طلایی جست‌وجو، حذف رکوردهای draft، رفتار بدون نتیجه و مرزهای دسترسی/محدودیت را بررسی می‌کنند.
- دامنه داده runtime فعلی بر رکوردهای ساختاریافته کتابخانه موجود است: ۱۳۲ اصطلاح، ۱۶ رکورد قانون و ۲۲ خلاصه مقاله؛ یادداشت‌های پژوهشی و داده‌های خارج از این سه مجموعه، خودکار وارد این مسیر نشده‌اند.

**تفسیر صحیح:** این یک موتور جست‌وجوی پژوهشی داخلی و deterministic است؛ نه دستیار گفت‌وگومحور کامل، نه RAG مبتنی بر LLM و نه مجوز ارائه پاسخ حقوقی قطعی.

### آنچه هنوز انجام نشده است
- اتصال رجیستری runtime به manifest مرکزی گزارش‌شده در محیط محلی `docs/knowledge/README.md` و `docs/knowledge/manifest.json`. این فایل‌ها در شاخه remote فعلی مشاهده نشده‌اند؛ قبل از انتقال باید با workspace محلی و GitHub تطبیق داده شوند.
- اتصال این مسیر به رابط Lawyer Copilot یا هر تجربه چت؛ مسیر فعلی فقط جست‌وجوی داخلی است.
- ارزیابی کمی retrieval با مجموعه طلایی گسترده و گزارش Recall@10، Precision@5 و nDCG@10؛ این معیارها هنوز اندازه‌گیری و تأیید نشده‌اند.
- پوشش کامل زنجیره اصلاح، نسخ، تاریخ اجرا، مقررات انتقالی، آرای وحدت رویه و آرای قضایی در رجیستری runtime.
- تأیید منبع اولیه و اعتبار روزآمد قوانین؛ وضعیت فعلی مجموعه حقوقی همچنان فاقد رکورد primary-source/current-validity تأییدشده است.
- جست‌وجوی معنایی/embedding؛ عمداً در MVP فعال نشده است.
- هیچ اتصال عمومی یا cache آفلاین برای API داخلی ایجاد نشده است.

### دو مسیر فنی بررسی‌شده
1. **گسترش رجیستری و جست‌وجوی قطعی موجود:** تطبیق manifest، provenance، فیلتر تاریخ/صلاحیت، بهبود واژگان و ارزیابی کیفیت.
2. **افزودن embedding/vector و مدل زبانی:** قابلیت بالقوه بهتر برای پرسش‌های پیچیده، اما با هزینه، پیچیدگی و ریسک citation نامعتبر.

**مسیر منتخب:** مسیر ۱؛ چون موتور deterministic و داده ساختاریافته حاضر است و هنوز کیفیت baseline به‌صورت عددی سنجیده نشده. مسیر ۲ فقط وقتی بررسی می‌شود که benchmark نشان دهد جست‌وجوی واژگانی به‌طور معنادار ناکافی است.

### چک‌لیست بعدی
- [x] پیاده‌سازی رجیستری runtime روی کتابخانه حقوقی موجود، بدون ساخت corpus موازی.
- [x] پیاده‌سازی جست‌وجوی قطعی داخلی و مسیر API فقط‌مدیر.
- [x] اتصال نتایج به evidence و research dossier با برچسب وضعیت منبع.
- [x] تست‌های اولیه جست‌وجو، دسترسی و محدودیت.
- [ ] تطبیق امن manifest محلی `docs/knowledge` با شاخه remote و ثبت اختلاف‌ها.
- [ ] تکمیل رجیستری مرکزی برای قوانین، اصلاحات، نسخ، آرای وحدت رویه، آرای قضایی و نظریات مشورتی؛ بدون کپی‌سازی داده موجود.
- [ ] افزودن فیلترهای معتبر effective-date، amendment chain، jurisdiction و conflict resolution به retrieval gateway.

- [ ] بررسی نهایی توسط وکیل مسئول؛ هیچ رکوردی صرفاً با نتیجه موتور جست‌وجو verified نمی‌شود.

### معیار پایان
اتصال دانش زمانی برای Lawyer Copilot پذیرفته می‌شود که هر نتیجه به رکورد canonical، source ID، نسخه، تاریخ اثر و وضعیت بررسی متصل باشد؛ draft و منبع نامعتبر از پاسخ قطعی حذف شوند؛ citation قابل بازبینی باشد؛ نبود یا تعارض منبع به امتناع روشن منجر شود؛ و benchmark retrieval حدنصاب مصوب را بگذراند. برش admin-only فعلی پیاده‌سازی شده، اما اتصال کامل دستیار حقوقی هنوز پایان نیافته است.

## 2. ارتقای بکاپ مادر دو

### اصل حفاظت
- بکاپ اصلی `VAKILSITE-MOTHER-TWO-20261105` یک baseline تاریخی و دست‌نخورده است؛ هرگز overwrite، rename یا حذف نشود.
- نسخه جدید باید با شناسه مستقل، تاریخ، ساعت و پسوند روشن ساخته شود؛ پیشنهاد شناسه: `VAKILSITE-MOTHER-TWO-PLUS-KNOWLEDGE-20261106`.
- بکاپ جدید باید از workspace واقعی و تأییدشده Termux تهیه شود تا تغییرات محلی و فایل‌های untracked نیز جا نمانند.
- GitHub checkpoint به‌تنهایی جایگزین آرشیو محلی کامل نیست؛ این دو باید جداگانه ثبت شوند.

### دو مسیر
1. **ساخت آرشیو از workspace فعلی:** تغییرات tracked و untracked را در یک snapshot واحد نگه می‌دارد و بهترین مبنا برای ادامه کار است.
2. **ساخت آرشیو صرفاً از Git commit:** تمیزتر است، اما تغییرات محلی ثبت‌نشده را حذف می‌کند و برای وضعیت فعلی قابل قبول نیست.

**مسیر منتخب:** آرشیو workspace فعلی، پس از preflight و فهرست‌برداری؛ چون هدف حفظ تمام داده‌های افزوده‌شده و تغییرات محلی است.

### محتوای الزامی بسته پشتیبان
- snapshot کامل فایل‌های پروژه، شامل کد، محتوا، docs/seo، docs/mavis، docs/knowledge، فایل‌های پژوهشی و فایل‌های rollback موجود.
- فهرست مسیرها، نوع فایل، اندازه و SHA-256 برای هر فایل.
- شناسه بکاپ، تاریخ و timezone، مسیر منبع، Git HEAD، وضعیت branch و خلاصه Git status.
- فهرست فایل‌های حساس یا حجیم مستثناشده؛ هیچ secret، token، کلید API یا داده محرمانه موکل وارد آرشیو قابل اشتراک نشود.
- راهنمای فارسی بازیابی با مسیر مقصد، ترتیب استخراج، نصب وابستگی‌ها و هشدارهای لازم.
- فایل checksum کل آرشیو و manifest مستقل.

### روش تأیید
- [ ] تأیید وجود و سلامت بکاپ مادر دو اصلی؛ فقط خواندن، بدون تغییر.
- [ ] بررسی فضای آزاد و فهرست کامل workspace.
- [ ] ثبت HEAD، وضعیت Git و همه فایل‌های untracked/modified.
- [ ] تعیین صریح exclusions؛ حذف فایل‌ها فقط با ثبت در manifest، نه حذف از workspace.
- [ ] ساخت آرشیو جدید خارج از پوشه پروژه و خارج از مسیر بکاپ قبلی.
- [ ] بررسی ساختار آرشیو و تعداد فایل‌ها.
- [ ] محاسبه SHA-256 و بررسی دوباره checksum.
- [ ] استخراج آزمایشی به پوشه موقت مستقل و مقایسه manifest/هش فایل‌ها.
- [ ] ثبت گزارش بازیابی و مسیر دقیق فایل‌ها.
- [ ] نگهداری بکاپ اصلی مادر دو به‌صورت immutable و نگهداری نسخه جدید کنار آن.

### محدودیت اجرایی ثبت‌شده
در زمان ثبت این سند، دسترسی مستقیم به filesystem خصوصی Termux در این نشست وجود ندارد. بنابراین آرشیو محلی جدید هنوز ساخته یا restore-test نشده است. هیچ ادعایی مبنی بر به‌روزرسانی موفق بکاپ محلی مجاز نیست تا خروجی واقعی Termux و checksum/restore test ثبت شود.
