# 03 — امنیت و حریم خصوصی

## 1. اصول

- Least Privilege و Zero Trust در مرزهای داده.
- جداسازی کامل Public و Private.
- کمینه‌سازی داده و محدودیت هدف استفاده.
- عدم افشای کلیدها و اسرار در مرورگر، Git، prompt یا log.
- کنترل مجوز در سمت سرور برای هر عملیات حساس.
- ثبت رخداد قابل ممیزی با پرهیز از ذخیره غیرضروری محتوای حساس.

## 2. طبقه‌بندی داده

| سطح | نمونه | قاعده |
|---|---|---|
| Public | محتوای منتشرشده سایت | قابل استفاده در Public |
| Internal | تنظیمات غیرمحرمانه دفتر | فقط کاربران مجاز |
| Confidential | مکاتبات داخلی و داده موکل | فقط Private با مجوز پرونده |
| Restricted | اسناد هویتی، اسرار، اسناد قضایی حساس، credentials | دسترسی محدودتر؛ ارسال به Provider تا تصویب ارزیابی ممنوع |

طبقه‌بندی نهایی و مبنای حقوقی پردازش داده باید پیش از ورود داده واقعی تصویب شود.

## 3. احراز هویت و مجوزدهی

- Supabase Auth فعلی می‌تواند پایه احراز هویت باشد، اما helper فعلی admin به‌تنهایی مدل مجوز MAVIS نیست.
- مجوزهای MAVIS مستقل از نقش‌های admin/editor سایت تعریف می‌شوند.
- هر API خصوصی در سمت سرور هویت و مجوز را بررسی می‌کند.
- RLS و SQL grants باید هم‌زمان و با اصل حداقل دسترسی طراحی شوند.
- شناسه رکورد، conversation_id یا case_id ورودی کاربر هرگز مجوز محسوب نمی‌شود.
- برای عملیات حساس، MFA یا احراز مجدد و ثبت دلیل اقدام بررسی می‌شود.

## 4. اسرار و تنظیمات

- OPENAI_API_KEY فقط در محیط سرور.
- OPENAI_MODEL و سقف‌ها از environment/config سمت سرور.
- NEXT_PUBLIC_* فقط برای مقادیر واقعاً عمومی.
- فایل‌های env در Git ممنوع.
- کلیدهای service role و provider هرگز در client bundle قرار نمی‌گیرند.
- rotation و لغو کلید در runbook عملیاتی مستند می‌شود.

## 5. حریم خصوصی Provider

در صورت استفاده از OpenAI Responses API:
- store:false به‌صورت صریح تنظیم می‌شود.
- این گزینه به‌معنی Zero Data Retention یا حذف همه لاگ‌های نظارتی Provider نیست.
- نوع داده مجاز، منطقه/شرایط پردازش، retention و گزینه‌های قراردادی باید پیش از استفاده از اطلاعات پرونده بررسی شوند.
- تا قبل از تأیید این ارزیابی، Public MVP فقط داده عمومی یا اطلاعات حداقلی و غیرحساس دریافت می‌کند.
- هیچ ادعای «عدم نگهداری مطلق» در UI یا سیاست حریم خصوصی مطرح نمی‌شود.

## 6. دفاع در برابر تهدیدهای AI

تهدیدهای مورد پوشش:
- Prompt Injection مستقیم و غیرمستقیم.
- افشای اطلاعات حساس و cross-session leakage.
- خروجی ناامن و XSS.
- Excessive Agency و Tool misuse.
- Data poisoning در منابع بازیابی‌شده.
- Vector/embedding isolation failure.
- Unbounded consumption و حملات هزینه‌ای.
- جعل استناد و misinformation.

کنترل‌ها:
- متن کاربر و اسناد بازیابی‌شده داده غیرقابل‌اعتماد تلقی می‌شوند.
- دستورهای سیستم در سمت سرور و نسخه‌بندی‌شده‌اند.
- Toolها allowlist و schema سخت‌گیرانه دارند.
- مجوز Tool مستقل از تصمیم مدل بررسی می‌شود.
- خروجی مدل قبل از render یا استفاده downstream اعتبارسنجی می‌شود.
- HTML خام مدل اجرا نمی‌شود.
- نتایج retrieval با tenant/workspace و permission فیلتر می‌شوند.
- محدودیت تعداد فراخوانی، timeout، token و هزینه اعمال می‌شود.

## 7. ابزارهای دارای اثر بیرونی

ارسال پیام، انتشار محتوا، حذف، تغییر پرونده، ثبت نهایی سند یا هر عملیات برگشت‌ناپذیر:
1. ابتدا پیش‌نمایش.
2. نمایش دقیق اثر و مقصد.
3. اخذ تأیید صریح کاربر مجاز.
4. اجرای سمت سرور با idempotency مناسب.
5. ثبت Audit و نتیجه.
6. امکان لغو/جبران در صورت پشتیبانی.

مدل نمی‌تواند تأیید انسانی را جعل یا دور بزند.

## 8. Rate Limit و کنترل هزینه

- Rate limit باید اتمیک و سازگار با چند instance باشد؛ حافظه process برای production کافی نیست.
- سهمیه بر اساس IP/session برای Public و user/workspace برای Private طراحی می‌شود.
- سقف هم‌زمانی، اندازه ورودی، طول خروجی، timeout و سقف هزینه اعمال می‌شود.
- پاسخ‌های خطا نباید جزئیات اسرار یا stack trace را افشا کنند.
- circuit breaker و kill switch برای Provider وجود خواهد داشت.

## 9. Logging و retention

- log عملیاتی: request_id، زمان، وضعیت، latency، provider/model، token/cost در صورت دسترسی، نتیجه policy.
- محتوای کامل پیام‌ها به‌صورت پیش‌فرض در log ثبت نمی‌شود.
- دسترسی به Audit محدود و قابل ثبت است.
- مدت نگهداری، حذف و پشتیبان‌گیری برای هر طبقه داده جداگانه تصویب می‌شود.
- درخواست حذف داده باید از backupها و replicaها نیز در سیاست مربوطه تعیین تکلیف شود.

## 10. موارد مسدودکننده انتشار

- نبود rate limit قابل اتکا.
- نبود سیاست حریم خصوصی و رضایت روشن.
- امکان دسترسی Public به Private.
- وجود کلید در client یا repository.
- نبود کنترل مجوز روی Toolها.
- ادعای حقوقی یا حریم خصوصی خلاف واقع.
- نبود kill switch و کنترل بودجه.
