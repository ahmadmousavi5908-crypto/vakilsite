## 5. نکات Provider که باید پیش از اتصال حل شوند

- اشتراک ChatGPT و API billing جدا هستند؛ اشتراک ChatGPT اعتبار API فراهم نمی‌کند.
- فهرست رسمی فعلی OpenAI API آلمان را در فهرست کشورهای پشتیبانی‌شده دارد و ایران در فهرست نیست. پشتیبانی از محل توسعه‌دهنده به‌تنهایی اثبات نمی‌کند که ارائه سرویس به کاربران واقع در کشور پشتیبانی‌نشده مجاز است.
- Responses API به‌طور پیش‌فرض response را ذخیره می‌کند؛ در صورت انتخاب باید `store:false` صریح باشد. این گزینه همه Abuse Monitoring Logs را حذف نمی‌کند.
- انتخاب Provider برای مخاطب هدف ایران نیازمند بررسی رسمی شرایط جغرافیایی، پرداخت، پردازش داده و قرارداد است. هیچ روش دورزدن محدودیت استفاده نخواهد شد.

## 6. گام‌های بعدی به ترتیب

1. تکمیل ماتریس Providerهای مجاز و قابل دسترس برای محل واقعی استقرار و کاربران هدف.
2. انتخاب backend اتمیک rate limit و طراحی دقیق privacy/consent.
3. افزودن تست‌های تکمیلی برای ورودی بدخواه، history ordering، provider failures و budget controls.
4. پیاده‌سازی OpenAI Adapter فقط در صورت احراز صلاحیت و پس از نصب نسخه رسمی تأییدشده SDK.
5. ایجاد Route عمومی با kill switch، rate limit اتمیک، timeout و پاسخ خطای امن.
6. اتصال UI مستقل چت به Route؛ حفظ launcher و شخصیت مصوب MAVIS و عدم دستکاری دکمه معرفی وکیل.
7. ساخت corpus حقوقی فقط از منابعی که مجوز ingest دارند و با وضعیت اعتبار قابل ممیزی.
8. بعد از تکمیل و تست، ادغام تغییرات محلی کارت همراهان و سپس مرور کامل رگرسیون سایت.
9. دستیار خصوصی، RLS و اسناد پرونده در milestone جداگانه؛ نه در MVP عمومی.
